# `wikiops_sdk.domain`

The domain package contains the provider-agnostic runtime models shared between the host, plugins, and providers.

## Re-Exported Public Surface

`wikiops_sdk.domain` exposes:

- `ExecutionContext`
- `Document`
- `DocumentRef`
- `DocumentVersion`
- `DocumentFormat`
- `ProviderCapability`
- `RefKind`
- `BaseMessage`
- `WarningMessage`
- `NoteMessage`
- `BaseOperation`
- `CreateDocumentOperation`
- `UpdateDocumentOperation`
- `CreateChildDocumentOperation`
- `Operation`
- `ChangeSet`
- `AppliedOperationResult`
- `ApplyResult`
- `OperationStatus`

## Context Model

### `ExecutionContext`

Mutable execution-time state shared during planning.

Fields:

- `run_id`
- `profile_name`
- `provider_name`
- `dry_run`
- `refs`
- `documents`
- `plugin_config`
- `input_data`
- `runtime_vars`

Use it as the plugin-facing runtime state object, not as a provider implementation detail.

## Reference And Document Models

### `RefKind`

Current logical reference kinds:

- `ID`
- `PATH`
- `ALIAS`

### `DocumentRef`

Portable document locator with provider namespace, kind, locator data, and optional hints.

It accepts extra fields, which lets providers carry provider-specific metadata when necessary.

### `DocumentFormat`

Current built-in format enum.

Current supported value:

- `MARKDOWN`

### `DocumentVersion`

Provider-agnostic concurrency metadata.

Fields:

- `token`
- `revision`
- `etag`

### `Document`

Portable document payload.

Fields:

- `ref`
- `title`
- `content`
- `format`
- `version`
- `metadata`

## Messaging Models

### `BaseMessage`

Common shape for planning messages.

Fields:

- `code`
- `message`

### `WarningMessage`

Structured warning emitted during planning.

### `NoteMessage`

Structured informational message emitted during planning.

## Capability Model

### `ProviderCapability`

Feature flags used to describe provider support.

Current values:

- `READ_DOCUMENT`
- `CHECK_EXISTS`
- `CREATE_DOCUMENT`
- `UPDATE_DOCUMENT`
- `CREATE_CHILD_DOCUMENT`
- `BUILD_LINK`
- `RESOLVE_BY_PATH`
- `RESOLVE_BY_ID`
- `HIERARCHICAL_PAGES`
- `VERSION_CHECK`

## Operation Models

### `BaseOperation`

Shared metadata for mutation operations.

Fields:

- `operation_id`
- `reason`
- `tags`

### `CreateDocumentOperation`

Fields:

- `operation`
- `ref`
- `parent_ref`
- `title`
- `content`
- `format`
- `metadata`

### `UpdateDocumentOperation`

Fields:

- `operation`
- `ref`
- `new_content`
- `expected_version`
- `format`
- `metadata`

### `CreateChildDocumentOperation`

Fields:

- `operation`
- `parent_ref`
- `ref`
- `child_title`
- `child_content`
- `child_format`
- `child_metadata`

### `Operation`

Discriminated union over the three supported operation types.

This lets callers validate heterogeneous operation lists while keeping runtime handling explicit.

## Planning Aggregate

### `ChangeSet`

Provider-targeted planning aggregate.

Fields:

- `plugin_id`
- `operations`
- `warnings`
- `notes`

Method:

- `is_empty()`

## Apply Result Models

### `OperationStatus`

Operation outcome status enum:

- `APPLIED`
- `SKIPPED`
- `FAILED`

### `AppliedOperationResult`

Per-operation result model.

Fields:

- `operation_id`
- `status`
- `message`
- `resolved_ref`
- `resulting_version`

### `ApplyResult`

Aggregate provider apply result.

Fields:

- `provider_name`
- `results`

Method:

- `has_failures()`

## Example

```python
from wikiops_sdk.domain import (
    ChangeSet,
    CreateDocumentOperation,
    DocumentRef,
    RefKind,
)

root_ref = DocumentRef(
    provider="demo",
    kind=RefKind.ID,
    locator={"id": "root"},
)

changeset = ChangeSet(
    plugin_id="wikiops.example",
    operations=[
        CreateDocumentOperation(
            parent_ref=root_ref,
            title="Architecture",
            content="# Architecture\n\nGenerated by WikiOps.",
        )
    ],
)
```
